## Модули
### Основные приложения
### Read API

Часть основного API отвечающая за ЧТЕНИЕ данных из базы данных

### Write API

Часть основого API отвечающая за ЗАПИСЬ данных в базу данных.
так как у неё выше отвественность в ней хранятся все 
файлы миграции основной базы данных

> [!NOTE]
> ### Для чего нужно разделять API на две части?
> На это есть несколько причин:
> #### Масштаб
> 
> Монолитное API при масштабировании может вызывать много проблем,
> связанное с лишним кодом.
> #### Разная нагрузка
> В контексте системы мониторинга можно разделить нагрузку:
> 
> *Запись* - Относительно дешевая операция *(добавить сервер, регистрация пользователя)*.
>
> *Чтение* - Намного тяжелее, помимо чтения из базы данных *(чтение списка серверов, пользователей)*
> также необходимо обновлять метрики условно каждые 5 секунд. Каждый такой запрос содержит
> очень много информации лишь об ОДНОМ сервере - сколько занято RAM, диска, список процессов, 
> логи.
